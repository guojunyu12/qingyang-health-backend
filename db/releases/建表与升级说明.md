# 轻养健康线上建表说明

契约 QY-MYSQL-1.1.0，MySQL **8.4 / InnoDB**，邮箱验证码身份。上线数据库凭据需由管理员配置，本交付不连接或修改任何线上数据库。

## 新建完整线上空库

1. 管理员创建数据库，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`；不向公网开放数据库。
2. 确认当前选中库没有业务表。备份与维护窗口由部署方安排。
3. 执行 `QY-MYSQL-1.1.0_full_install.sql`。它包含冻结V001和邮箱V002、安全副本元数据V003、认证加密重试V004及迁移历史登记，共44张业务表、1张迁移历史表。
4. 不使用 `--force` 忽略错误，不关闭外键。DDL隐式提交，任何错误立即停止，不把ROLLBACK当作DDL恢复手段。
5. 配置后端的独立运行用户与迁移用户。应用用户仅授予本业务库 SELECT、INSERT、UPDATE、DELETE；迁移账户单独保管。
6. 设置服务端每连接UTC、环境密钥、Redis及SMTP，执行接口契约查询和双用户验证后再放流量。

示例（密码由终端交互输入，不放命令行）：

```sh
mysql --host=数据库地址 --user=迁移账号 --password 目标空库 < QY-MYSQL-1.1.0_full_install.sql
```

新库不需要先单独跑V001，也不能再跑一次此完整文件。文件不导入演示积分、用户健康历史、管理员身份或供应商凭据。

## 已部署V001的数据库

禁止执行完整安装文件。先核验V001结构与校验记录，依次执行 `db/migrations/V002__email_identity.sql` 、`V003__safe_media_metadata.sql` 和 `V004__encrypted_auth_retry.sql`，或由后端 `npm run migrate` 统一登记。

V002要求users及auth_challenges没有旧手机号身份。若已有手机号用户或挑战，脚本的迁移入口会拒绝自动转换；必须先制定实名账号绑定/数据迁移方案，不把手机号直接当邮箱。手工直接执行SQL前，也必须自行检查这个前提。

MySQL DDL非事务原子。V002由三条ALTER组成；若中途失败，保留原日志、检查实际结构并前向修复，不能直接重跑全部ALTER或删除数据库。

## M01专属表参考

`M01_12_tables_reference.sql` 包含：users、auth_challenges、user_sessions、refresh_tokens、media_assets、notification_subscriptions、notifications、notification_deliveries、idempotency_requests、outbox_events、user_roles、audit_logs。

此文件用于M01独立审阅和空库结构验证；不登记完整应用V001/V002/V003/V004版本。团队完整后端用全库安装文件，不能在同一库先执行12表参考再执行全库安装。

## 关键口径

- 业务ID为应用生成小写UUID v4，日期UTC，业务日Asia/Shanghai。
- 邮箱密文及HMAC摘要替代手机号；验证码摘要、刷新凭据摘要不存明文。
- 本地私有媒体存储为本轮已选适配器，正式部署需持久化受限磁盘及备份。
- Web Push/App Push待配置，能力接口返回false，不因建表成功声称推送可用。
- M05零积分开户、跨模块通知业务校验及真实业务QueryPort需对应模块接入后整体验收。

V003为媒体安全副本增加独立MIME/字节数。若此前已有ready文件，需要由维护流程从可信安全副本重建元数据；本轮上线新空库不含旧媒体。缺少安全元数据的旧文件不对外签名。

V003升级前已有媒体：先备份私有媒体并停止API流量，执行 `npm run media:backfill` 预览数量，再执行 `npm run media:backfill -- --apply` 从保留原文件重新完整校验并生成安全副本。损坏或丢失原文件会明确进入rejected，确认结果后恢复服务。

提供 `QY-MYSQL-1.1.0_upgrade_from_V001.sql` 给已经核验并登记V001的空账号环境。它在执行ALTER前用临时CHECK表拒绝旧手机号身份、缺失/错误迁移记录或已升级版本；仅适用于恰好V001，其他版本请用迁移工具按序升级。
