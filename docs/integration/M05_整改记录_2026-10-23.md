### 复验入口

各仓分别执行锁安装、typecheck、build、test；后端测试必须显式加载独立 `_test` 环境。环境示例只使用变量名，不包含凭证。

```sh
# backend：本地环境文件必须指向独立测试库、Redis 和私有媒体目录
node --env-file=.local/test.env --import tsx --test tests/*.test.ts
# admin live 后端：AUTH_NO_LISTEN=1，DB_HOST 仅本机，数据库必须 _test 后缀
M05_LIVE_TEST=1 M05_E2E_CONFIRM_DATABASE=<隔离测试库名> M05_LIVE_PORT=4302 \
  node --env-file=.local/browser.env --import tsx tests/support/live-m05-api.ts
# admin：先以对应 API_INTERNAL_URL 构建；详细命令见后台浏览器记录
pnpm test:e2e
ADMIN_LIVE_FIXTURE_FILE=<backend>/.local/m05-browser-fixture.json \
ADMIN_LIVE_MAIL_FILE=<backend>/.local/m05-browser-mail.json \
ADMIN_LIVE_H5_URL=http://127.0.0.1:3301 \
API_INTERNAL_URL=http://127.0.0.1:4302 pnpm test:e2e:live
# H5 专用 live：独立身份/目录测试入口，详情延续已有 M02/M03 文档
QY_LIVE_E2E=1 QY_E2E_CODE_FILE=<backend>/.local/m03-e2e-code \
  npm run test:e2e -- tests/e2e/nutrition-live.spec.ts
```

端口必须与 H5 构建时 rewrite 和测试库 APP_ORIGIN/ADMIN_ORIGIN 一致；本轮额外用 3301/3401/4302/4303 避开日常前端。原 health/nutrition live 入口与测试配置需配套使用，默认测试中的 skip 不代表真实通过。本轮明确另跑上述 3 次 live 变体。
