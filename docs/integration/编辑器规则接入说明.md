# 将统一规范放入自己的编辑器

每位成员在自己实际开发的 H5、后端或后台仓库分别操作。文件来自主整合窗口发布的同版本资料包，不从旧聊天里拼接。

## 1. 放置文件

将《团队开发与Git提交规范》《模块交付与PR说明模板》《模块合并规范》《模块合并台账》和本说明放进仓库 `docs/integration/`，保留原文件名。不要覆盖自己已有业务代码、环境文件或整份 AGENTS.md。

## 2. 追加到根目录 AGENTS.md

没有此文件就新建；已有则追加以下段落，保留 Next.js 自动维护块及原有规则：

```markdown
## 轻养健康 App：统一开发与交付规则

开始任何开发、改动、审查、提交或合并前，必须读取：
1. docs/integration/团队开发与Git提交规范.md
2. docs/integration/模块合并规范.md
3. docs/integration/模块合并台账.md
提交 PR 使用 docs/integration/模块交付与PR说明模板.md。

主整合窗口负责后续整合；从其指定的分支和 SHA 开发，不能默认旧 main。
只修改分配模块范围，保留已验收功能；重复业务未确认时保留现有实现。
复用正式 M01 邮箱身份、统一 API、事务/幂等/Outbox，不接入独立开发身份或重复底座。
公共入口、契约、Worker、依赖及迁移由主整合窗口统一装配。
代码遵循规范格式；提交使用明确文件白名单及 type(scope) 标题。
交付写清三仓库配套 SHA、实际测试、数据库变化和未完成项。
不得自行合 main、发布生产、强推共享分支、覆盖他人工作或重置数据库。
规则缺失、版本冲突或基线不明确时先报告具体缺项，不猜测绕过。
```

## 3. 在编辑器会话中启用

Codex 的仓库入口为 AGENTS.md。其他编辑器的规则入口随安装版本不同，可将上面同一段落添加至该编辑器支持的项目规则中，引用仓库相对路径；不要维护另一个相互矛盾的正文版本。

不确定编辑器是否自动读取时，在本任务第一次指令明确附上 AGENTS.md 和上述三个规范文件，并发送：

> 先读本仓库 AGENTS.md 和 docs/integration 中的团队开发规范、模块合并规范、最新台账，再工作。请列出你读取的版本、实际分支与 HEAD、本轮允许修改范围、要保留的已有功能及计划验证方式。按统一交付模板提交候选 PR，交主整合窗口审核，不自行合 main。

仅粘贴路径不保证所有编辑器都会自动读取。检查助手是否实际读取文件；没有读取就显式附加文件。新任务、换仓库、规范升级后重新核实。

## 4. 同步和提交

规范版本以主整合窗口发布为准。更新时比较差异，保留项目原有附加规则；新增冲突交主整合窗口统一决定。规则文件和 AGENTS.md 变更单独提交，例如 `docs(shared): 接入团队开发与提交规范 v1.0.0`。

本资料包不包含实际环境配置或密钥，也不表示 GitHub CI/分支保护已经启用。规则先由成员与主整合窗口人工执行，自动化配置另行实施。
