## 1. 重复实现 M01 公共能力

问题：交付包含独立开发登录、上传及幂等实现，生产页面默认使用自己的请求适配器，并存在测试身份和开发能力接口依赖。直接接入不能复用当前 M01 的正式登录和公共运行机制。

整改要求：

- 从正式应用装配和发布范围中移除重复的登录、上传服务器、测试账号及公共幂等壳；确需保留的测试夹具仅限隔离测试环境，不能注册到正式应用。
- 前端统一调用 M01 请求器和接口，使用现有邮箱登录态、CSRF、刷新会话及上传流程，不再维护另一套公共认证机制。
- 后端统一调用 M01 身份、媒体、事务、幂等和 Outbox 能力；用户 ID 从服务端登录态取得。
- 适配现有上传的 Cookie/CSRF 校验，等待资源 ready 后才创建识别任务。
- 保留 M03 自身的业务约束：同一识别任务只能确认一次、任务领取和终态条件更新。这些约束不能因移除重复公共幂等实现而被删除。

验收：正式代码不请求 `/__dev/session` 或依赖开发能力接口；登录后可走 M01 上传；跨用户访问被拒绝；相同请求重复提交和同一识别任务重复确认均不会重复记餐或发奖。

状态：正式代码已接入，M01/M02保护回归和M03确定性联调通过；真实供应商和M05单列。

已补齐在线 VisionPort 与正式注册，并验证超时/取消机制。剩余工作：配置有效 API Key，在目标部署环境完成真实照片识别。环境变量本身不能把 Ollama 调用协议转换为在线接口。

验收：部署服务器无需 Ollama 即可完成真实识别；浏览器没有供应商密钥；用户确认前不生成餐记录。
