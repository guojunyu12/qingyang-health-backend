# M02 手动验收

本轮按用户要求不新增自动化测试。下面的验收通过页面手动操作完成；项目原有测试保留，历史结果在 docs/M02/HANDOFF.md 中单独记录。

## 1. 先确认能启动

按 README 安装依赖、配置 `.env.api` 中的 MySQL 8.4 服务。

- 空库第一次启动：`npm --prefix tools/m02-dev run start -- --init`。
- 已经初始化过：`npm --prefix tools/m02-dev run start`，不重复执行 V001。
- 前端：另开终端执行 `npm run dev`。
- 浏览器打开 http://127.0.0.1:3001/dashboard。

**通过条件：** 页面能打开，顶部有明确的本地联调横幅，选择账号后显示健康记录或空状态，没有把缺少服务伪装成演示健康史。

## 2. 健康档案

1. 选择测试账号 A，点击“设置个人目标”或“编辑档案”。
2. 主动填写目标体重、饮水目标、基础热量目标和健康目标；可选项可留空。
3. 保存、刷新页面，再打开档案。

**通过条件：** 输入持久保存；可选项未填就为空；当天没有测量时不生成一条体重记录。

可选并发检查：同账号在两个页面打开同一版本的档案，先保存第一个，再保存第二个。第二个页面应提示版本冲突，并允许重新加载；不得静默覆盖。

## 3. 饮水新增与持久化

1. 在今日看板记下当前饮水量。
2. 点击两次“喝一杯水”，每次等待保存结束。
3. 刷新页面，查看下方两条独立记录。

**通过条件：** 相比初始累计增加 500 ml，产生两条独立记录；刷新仍存在。首次当日积分最多一份；本地奖励来自明确标记的 M05 测试适配器。

点击“手动记录 / 补录”后选择一个历史日期、时间和饮水量。保存前应看到上海日期归属预览；保存后切换到相应日期。历史补录不补发日任务积分。

## 4. 体重与删除确认

1. 点击体重卡片右上角“＋”，记录一次测量。
2. 再记录一次不同的测量，查看当天最新值。
3. 点击某条记录的“删除”，先选“保留记录”，确认没有消失。
4. 再点删除并明确确认。

**通过条件：** 同日多次测量保留为独立记录；删除最新测量后回退到剩余最新值。取消删除不改变数据。

同样检查饮水删除：累计应减少，但已有积分不被删除，也不因此恢复当天领奖资格。

## 5. 日期、目标与大屏

1. 在今日看板切换日期，检查饮水和体重属于所选日期。
2. 历史日期点击“返回今天”，回到当前上海业务日。
3. 打开“健康数据大屏”，切换近 7 天、近 30 天。
4. 点击体重测量点和饮水日期，查看图下明细。

**通过条件：** 每个范围保留完整日期网格；缺体重与心情显示为空，体重不跨缺测日期连线；未记录的饮水不计入均值分母。历史页面目标使用当前目标口径。

## 6. 账号隔离与布局

1. 记住账号 A 的体重或饮水，切换测试账号 B。
2. 账号 B 尚无记录时应显示空状态，不出现 A 的记录。
3. 返回 A，应看到 A 自己的已保存事实。
4. 调整浏览器为手机、中等窗口和桌面宽度，查看体重入口、弹层和大屏。

**通过条件：** 账号互相隔离；体重入口不会在中等宽度消失；页面无整体横向溢出，表格/长图仅在自身区域滚动。Escape 或取消关闭弹层后，焦点回到原入口。

## 7. 验收边界

- 本仓库验收 M02 健康数据与页面，不把其他组原有演示页面计为真实完成。
- 本地 MySQL 持久化是真实的；账号、积分和跨模块查询的联调适配器有明确标记。
- 正式 M01 登录/事务/幂等与 M05 真正发奖内核仍需团队注入；其他组真实数据的整合验收尚未完成。
- GitHub 公开源码发布不等于可公开访问的线上 API 或健康服务。
